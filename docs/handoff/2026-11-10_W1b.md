# Handoff: W1b Earthdata downloads (Colab notebook + helpers)

## 1. What was done (plain English)
- **Built the code and a Colab notebook for the downloads that need your Earthdata login. The downloads themselves have NOT been run**: this session has no Earthdata login (and must not type one), so no real SMAP, MODIS, NASADEM, GRACE-FO, HLS, ECOSTRESS or GEDI file was fetched.
- **Notebook:** `notebooks/w1b_earthdata_colab.ipynb`, 11 code cells in the order of the plan: setup, login, grid, then SMAP, MODIS, NASADEM, GRACE-FO (64 districts), HLS, ECOSTRESS, GEDI (the two demo tiles), and a final listing. You type your username and password in cell 2 (hidden box). They are used for the AppEEARS login and the `earthaccess` login, held in memory, never written to a file or printed.
- **Product facts were read, not remembered:** product IDs, layer names, fill values, scale factors, DOIs and start dates come from the public AppEEARS product API and NASA CMR (no login needed), 10 Nov 2026. Source links were opened and returned 200. They are in `src/acquire/w1b/products.py` (`PRODUCTS`).
- **Helpers (tested):** `src/acquire/w1b/` (request bodies, small AppEEARS client, masks and unit conversions, district tables, DEM strips, GEDI cells) and `src/compute/district_grid/regrid.py` (mean onto the 0.1° grid, nearest cell, slope). These implement the rules already in `docs/harmonisation.md` (SMAP/MODIS/NASADEM = mean, GRACE-FO = nearest, flagged regional).
- **Why a zip:** the repo is private, so Colab cannot clone it. `python scripts/pack_w1b.py` makes `data/raw/w1b_pack.zip` (0.4 MB, gitignored); cell 1 asks you to upload it once.

## 2. How to run it (you)
1. `python scripts/pack_w1b.py`
2. Open `notebooks/w1b_earthdata_colab.ipynb` in Colab (File > Upload notebook). Run cells 1 to 3.
3. Run cell 4 (SMAP) and look at the printed cross-check against the five point files we already have (r and mean difference per district).
4. **MODIS (cell 5) is set to `YEARS = [2023]` on purpose.** Check the printed "share of pixels kept" and the saved file, then change it to `list(range(2001, 2025))`. It is resumable (finished years are skipped). It is the heavy one: a year at 250 m over the whole country is large, and I did not measure the time.
5. Cells 6 to 10 are independent. Copy the small CSVs from Drive (`cropshift_w1b`) into `data/processed/`. Keep the `.npz` files out of git (raw/HF only). Cell 11 flags anything over 5 MB.
6. Cell 10 downloads one GEDI file of about 0.5 GB.

## 4. Open questions (also in `docs/PROJECT_STATE.md`; none is guessed)
1. MODIS `pixel_reliability`: code keeps value 0 as "good". Recalled from the LP DAAC guide; the API only gives the range 0 to 3.
2. HLS `Fmask`: bits 1 (cloud), 2 (adjacent), 3 (shadow), 4 (snow/ice) masked. Recalled from the HLS guide; the API only gives fill = 255.
3. GEDI L4B unit (Mg/ha) is confirmed from the file metadata the cell prints.
4. GRACE-FO: I chose the CRI-filtered grid (JPL recommends it for most land hydrology). Variable names `lwe_thickness` and `uncertainty` are checked at run time.
5. "Demo fields" = the two 20 km T3 tiles (Feni, Cumilla); the HLS year 2024 is my choice. Column names say `tile_mean_...` so they are not mistaken for single-farm values.
6. The 64 districts share about 48 GRACE-FO cells in the synthetic check; that is expected and the cell used is recorded per row, so analysis can say "regional".

## 5. Honest limits
- SMAP's 9 km vs the 0.1° (about 11 km) grid means 1 to 2 SMAP pixels per cell. AppEEARS reprojects to latitude/longitude with its own resampling.
- NASADEM cells on the coast include sea pixels; district polygons are land, so the effect is small but not zero.
- GRACE-FO is a regional signal (about 300 km effective). GEDI mostly measures trees, not field crops: context only.
- The district × season feature table has not been extended with these columns yet; that needs the real files (next step after you run the notebook).
