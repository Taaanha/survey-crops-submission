# Handoff: T2 Farmer priorities: 2026-10-24

## 1. What was done (plain English)
- **Built `src/compute/priorities/`**: four priorities (save water, soil health, lowest risk, flood safety) with weights 0-1. Weights are scaled to sum 1; all zero is a clear error. Each priority has one metric read from the rotation module's summary; metrics are min-max normalised across the candidate rotations (1 = best); score = sum(weight x normalised). Every component (raw value with provenance, normalised, weight, contribution) is returned. No other factor.
- **New API `POST /api/v1/rotation/rank`** `{district, weights}`: ranked rotations with components, `unranked` rotations with reasons, notices, and provenance. The path has the `/api/v1` prefix like every other endpoint. The slow evaluation is cached per district, so changing the weights re-scores instantly.
- **Small addition to the rotation module**: `problem_years_by_hazard` in the summary and `hazards_hit` per modelled slot, so "flood-related problem years" comes from the public output, not from a private function.
- **Mock**: `web/mock/rotation_rank.json` (a real Cumilla response, marked `is_mock`).
