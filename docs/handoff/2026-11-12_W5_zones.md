# Handoff: W5 follow-up, shapely proof and relative vulnerability zones (12 Nov 2026, branch w5-vulnerability, cut from main after PR #44)

## Part 1: does the deployed API need shapely? No.
`tests/api_deploy/test_no_shapely.py` runs a fresh interpreter with `sys.modules['shapely'] = None`, imports `app.py` and calls every route found in `app.routes` (22 calls: the five older endpoints, soil, rank, ask, images, enso, warnings, root, docs, and the five `/api/v1/map/*` routes). Network is disabled in the probe.
- **Import chains that still reach shapely: none.** Zero attempts recorded, no 500s, and `district_grid.boundaries` / `district_grid.grid` (the only two files that import shapely) are never loaded. Nothing was added to `requirements-api.txt`.
- The probe was checked against a fake app whose route imports shapely: it reports the chain and the 500.
- A new route without a probe entry fails the test ("add a probe call for ...").
- Extra finding: `requirements-api.txt` also omits rasterio. On a machine that has `data/raw/opera_layers` but no rasterio, `proj_guard.apply()` raised RuntimeError and the passport returned 500. Fixed (caught, gives "not assessed") and tested. The real deployed API has no `data/raw`, so it never hit this.

## Part 2: zones (passport fields only, data already in the repo)
`src/compute/map_layers/zones.py`; every zone is labelled "relative ranking within this tile, our choice, not a cited vulnerability class".
- **Low-lying**: elevation at or below the 33.3rd percentile of the whole NASADEM tile (not the window). Cumilla tile: cut 8 m, 38% of the tile (whole-metre ties; the share is reported).
- **Flood-exposed**: T3b open-water days (upper bound, 2024); 0 only where observed with no event, unknown stays None; exposed = at or above the 66.7th percentile of observed pixels and above 0 days. Cumilla cut is 0 days, so it means any open water (about 10% of observed pixels). Without `data/raw/opera_layers`: "not assessed (layer not in the repo)".
- **Overlap**: three-valued AND; the flood layer is read at the nearest pixel centre for each NASADEM pixel (grids not aligned).
- **Cold-prone, erosion, water-stress**: not assessed, each with a reason and a source.
- Window results on this machine (15 x 15): CUM-ARF-01 low 186/225, flood 6/220, both 5/220; CUM-BRRI-02 low 154/225, flood 9/223, both 5/223 (unknown pixels not counted as 0).
- API: no new route; shape change proposed in `docs/contract_change_proposals.md` section 12. `web/app/map.html` only draws the grids and texts; `map_routes.py` adds the zones to `provenance`.
