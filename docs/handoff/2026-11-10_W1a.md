# Handoff: W1a boundaries, common 0.1° grid, POWER + IMERG for 64 districts

## 1. What was done (plain English)
- **Boundaries.** geoBoundaries gbOpen Bangladesh ADM2 (64 districts). Licence read from the geoBoundaries API on 10 Nov 2026: **CC BY 3.0 IGO** (original source BBS via OCHA ROAP, boundary year 2020). Saved as a simplified GeoJSON, 690 KB, in `data/reference/bgd_adm2_districts.geojson`, with the licence and source inside it. Attribution has to be shown wherever the map appears.
- **Common grid.** The IMERG 0.1° grid over the Bangladesh box (52 × 64 cells). Each district gets exact area-fraction weights per cell, and district means ignore cells with no data and report how much of the district had data (`src/compute/district_grid/`). Rules per dataset are in `docs/harmonisation.md`.
- **IMERG for 64 districts.** NASA GPM IMERG V07 Final Run daily, 2001-01-01 to 2025-09-30, **9,039 days, none missing**, through the free earthaccess/OPeNDAP subset route we agreed (about 25 minutes of download with 8 workers). Every day came from the `V07B` file. District polygon means are in `data/processed/imerg_polygon_daily_wide.csv.gz` (764 KB).
- **POWER for 64 districts.** Daily 2001-01-01 to 2026-08-31 at each district's query point (centroid, or a point inside the polygon). POWER echoes the query point back, so shared cells were found from the data: **45 distinct temperature series for 64 districts; 34 districts share a POWER cell with another** (`data/processed/power64_cell_groups.csv`). POWER rain is not used.
- **Feature table.** `data/processed/district_season_features.csv`: 64 districts × 24 season years (2001–2024) × 3 seasons = 4,608 rows, 8 value columns, plus `district_season_features_columns.csv` (dataset, unit, source URL, years covered per column). A season total is NaN unless every day was observed; here all 4,608 rows are complete.
- **PROJ guard** (see section 3).

## 2. Checks that the numbers are right
- **Grid check:** for the five live districts, the cell under the old Giovanni point in the new subset equals the old Giovanni file to within **0.005 mm on all 9,039 days** (that is the old file's 2-decimal rounding). So the index arithmetic and cell alignment are right.
- **Polygon mean vs point cell (total rain, 2001–2025):** Cumilla 1.019, Feni 1.021, Brahmanbaria 0.994, Noakhali 1.104, Sylhet 0.987. Noakhali's polygon is about 10% wetter than its single old point cell, so the old five-district point numbers were not far off but not identical either. This is expected, not a bug.
- **Coverage:** every district has IMERG data on 100% of its weight on every day. The smallest district by area (Narayanganj) spans about 6 cells.
- **Plausibility:** mean kharif2 (Jul–Oct) rain: Sylhet 1739 mm, Feni 1536, Cumilla 1279, Khulna 1327, Dhaka 1159, Rajshahi 915. Wettest in the northeast, driest in the northwest, as expected.

## 3. PROJ guard (so "EPSG code is unknown" cannot come back)
- **Cause, confirmed:** on this machine `PROJ_LIB` points to `D:\Program Files\PostgreSQL\17\share\contrib\postgis-3.6\proj`, whose `proj.db` is too old for rasterio's PROJ. Without the guard, `CRS.from_epsg(32646)` fails with "The EPSG code is unknown". `GDAL_DATA` is also set to PostgreSQL's folder, so the guard fixes that too (small addition beyond what you asked, same cause).
- **Fix:** `src/compute/common/proj_guard.py` finds rasterio's bundled `proj_data` **without importing rasterio**, then sets `PROJ_DATA`, `PROJ_LIB` (and `GDAL_DATA`), overriding any existing value.
- **Where it runs, before rasterio or pyproj load:** root `conftest.py` (covers `src` and `tests`); `scripts/_proj.py` (`import _proj` as the first import) in `build_layers.py`, `fetch_dswx.py`, `fix_fixture_meta.py` and the new `fetch_power64.py` and `build_district_features.py`; `fetch_imerg_bgd.py` calls the guard directly.
- **Tests:** `src/compute/common/test_proj_guard.py` — the bundled folder has `proj.db`; a subprocess started with a wrong `PROJ_LIB`/`PROJ_DATA` still resolves EPSG 4326 and 32646 after the guard; the CRS lookup works in the test process.
- **Rule for new scripts:** any script that imports rasterio, pyproj or geopandas must `import _proj` first (also written in `docs/PROJECT_STATE.md`).
