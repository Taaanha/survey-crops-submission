# farmer priorities (T2)
Layer: 1 compute
Code: src/compute/priorities/core.py
Purpose (2–3 sentences): Re-ranks the rotations from the rotation module by what the farmer says matters (save water, soil health, lowest risk, flood safety). Each priority has one metric taken from the rotation summary; metrics are min-max normalised across the candidates (1 = best), and the score is the weighted sum. Every component (raw value with provenance, normalised value, weight, contribution) is returned, so the screen can show the reasoning; there are no hidden factors. A record of past seasons (2001-2024), not a forecast.
Public API (exact signatures + one-line description each):
- `normalise_weights(weights)` : validates {save_water, soil_health, lowest_risk, flood_safety} (each 0-1, missing = 0), scales them to sum 1; raises PrioritiesError for all-zero, unknown keys, out-of-range or non-numeric values.
- `score_rotations(evaluations, weights, field_profile=None)` : ranks `evaluate_rotation` results; returns weights (requested and normalised), metric definitions, `ranked` (rank, score, components) and `unranked` (rotation, reason, how_to_include).
- `evaluate_candidates(district, context=None, years=None)` : `evaluate_rotation` for every candidate rotation (the slow step; the API caches it).
- `rank_rotations(district, weights, context=None, years=None, field_profile=None)` : the two above in one call.
- `flood_safety_raw(summary, field_profile=None)` : flood-related problem-year share (TODO hook for the T3 field water profile; raises NotImplementedError if a profile is passed).
- Class PrioritiesError (a ValueError) : unusable weights; the API turns it into BAD_PARAMETER.
Inputs (data files / other modules) and their provenance: only the public output of `rotation.evaluate_rotation` / `candidate_rotations`: `irrigation_mm_worst20`, `legume_count`, `problem_years`, `n_years`, `problem_years_by_hazard`. Each raw value keeps the provenance of the rotation measure it came from (shares add a note saying "X of N years").
Outputs (shape + units + provenance fields): `{"weights", "metrics", "ranked": [{"rank","id","rotation","problem_line","score","components"}], "unranked": [{"id","rotation","reason","how_to_include"}]}`; a component is `{"label","metric","direction","raw" ({value, unit, provenance} or null),"normalised","weight","contribution","no_contrast","note"}`. Score = sum of contributions (exactly), 0 to 1.
Reference tables used (data/reference/*.csv rows): none directly (through rotation).
Tests (file names + what each proves): tests/priorities/test_priorities.py (property: raising save_water never lifts a higher-irrigation rotation over a lower one; weights are normalised, all-zero is a clear error; contributions sum to the score within 1e-9; min-max direction; gaps are unranked, never zero), tests/priorities/test_priorities_real.py (real Cumilla: per-hazard counts equal a hand count; ranking is reproducible), src/api/test_rotation_rank.py (contract of POST /api/v1/rotation/rank vs web/mock/rotation_rank.json).
Known limitations / honest caveats:
- Flood safety is the share of past seasons with a waterlogging problem at the district point, only for crops with a sourced waterlogging limit (mustard, lentil). Wheat and boro have none, so with flood_safety weight above 0 they are listed as `unranked` ("not assessed"), not treated as safe. TODO(T3): replace with the field water profile.
- Soil health = legume count. The flags are now sourced (crops.csv, 24 Oct 2026: lentil and mung bean yes; rice, wheat, mustard, potato no). A crop with a blank flag makes its rotation's legume count *unknown*: with soil_health weight above 0 that rotation is `unranked` (never scored as 0 legumes). When all candidates are equal on a metric, each gets 0.5 and `no_contrast: true` (no division by zero, no NaN).
- Every `unranked` entry has a `how_to_include` hint (which priority is not assessed and for which crop; set that weight to 0 to compare it on the other priorities).
- Risk = problem years / N for assessed hazards only (infeasible years are not counted). Boro rice has no sourced hazard, so it is unranked whenever lowest_risk or flood_safety has weight.
- Min-max normalisation is relative to the candidates shown: scores compare these rotations with each other, they are not absolute. When all candidates are equal on a metric its normalised value is 0.5 (flagged `no_contrast`). Ties in score are broken by rotation id.
