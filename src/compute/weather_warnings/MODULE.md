# weather warnings (api-weather-warnings)
Layer: 1 compute (plus the fetcher in src/acquire/open_meteo.py and the route in src/api/warnings_routes.py)
Code: src/compute/weather_warnings/core.py
Purpose (2–3 sentences): Compares the daily weather outlook for a district point (Open-Meteo, non-NASA partner data) with thresholds that have a source row in `data/reference/`. A threshold with no usable source is skipped and reported, never used. No warning exceeded means an honest empty list.
Public API (exact signatures + one-line description each):
- `load_thresholds(reference_dir=REFERENCE_DIR)` : returns `(thresholds, skipped)`. Each rule in `RULES` names a CSV row (file + item); the row is used only if it has a single number, a real http source link, and no placeholder / suspect / fabricated / gap note.
- `evaluate_days(days, thresholds)` : `days` = `[{"date","rain_mm","tmax_c","tmin_c"}]` (None = not assessed). Returns one warning per (type, date): `type` (heavy_rain / heat / cold), `date`, `expected` {value, unit}, `threshold` (the most severe exceeded level, with its source), `crops` (crop-specific levels exceeded, with stage), `action` {en, bn}.
- `RULES` : the table of rules (which reference item, which weather field, which comparison).
Inputs (data files / other modules) and their provenance: `data/reference/r03_heavy_rain.csv` (BMD heavy 44 mm/24 h, very heavy 88 mm/24 h; news report of the BMD scale), `crop_thresholds.csv` (heat at flowering: mustard 29, wheat 31, lentil 32, boro 35 °C), `r04_cold_injury.csv` (BAMIS Tmin below 10 °C for boro, mustard, potato). Weather numbers come from `src/acquire/open_meteo.py` (live, then cache per point per day, then `demo_fixtures/openmeteo_<district>.json`).
Outputs (shape + units + provenance fields): see `GET /api/v1/warnings` in `docs/contract_change_proposals.md` section 15. Every measure carries `src` ids that resolve in `provenance[]` (`om` = Open-Meteo with retrieved date and request URL; `th_xxxxxxxx` = the reference row's source).
Reference tables used (data/reference/*.csv rows): the three files above. Rules whose rows are marked SUSPECT / PLACEHOLDER (`wheat.cold.bamis_warning_tmin`, `aman_rice.cold.flowering_tmin`) are in `RULES` on purpose and show up in `skipped`.
Tests (file names + what each proves): tests/weather_warnings/test_weather_warnings.py (normal day = empty list, heavy-rain day, very heavy leads, hot day lists crops, cold uses less-than, missing = not assessed, unsourced / placeholder / suspect / bad-link rows skipped, real CSVs); src/api/test_warnings_route.py (live, heavy rain, no banned words, Open-Meteo down -> cache -> fixture -> clear error, src ids resolve, Dockerfile ships fixtures).
Known limitations / honest caveats: (1) The stage a crop is at is NOT checked: heat limits are for flowering, so a hot day in November is shown as "can hurt if your crop is at that stage". (2) The rain limit is a point (station) scale applied to an ~11 km grid cell. (3) Action texts (EN and BN) are our wording, AI-written, not from a source; Bangla needs native review. (4) Open-Meteo is not NASA data.
