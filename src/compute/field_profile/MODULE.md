# field water profile (T3a stacks, T3b per-pixel flood metrics and layers)
Layer: 1 compute
Code: src/compute/field_profile/core.py, src/compute/field_profile/access.py, src/compute/field_profile/events.py, src/compute/field_profile/profile.py, src/compute/field_profile/hf.py
Purpose (2–3 sentences): Reads NASA OPERA DSWx-HLS (optical) and DSWx-S1 (radar) water maps for a 20 km box around a district point and turns them into one 30 m stack per district: for every date, each pixel is 1 (water), 0 (not water) or 255 (no observation). This is the data step for the field water profile (inundation days, drain date, events; later sessions). "Box" is the 20 km window around the district point, not the administrative boundary (boundary source is UNVERIFIED).
Public API (exact signatures + one-line description each):
- `opera_coverage(district, start, end)` : which DSWx-HLS / DSWx-S1 granules touch the box (counts per week and date, first date, granule IDs and URLs); metadata only, no downloads.
- `build_water_stack(district, start, end, out_dir, manifest_dir=None)` : builds the per-date stack (npz, outside git) and the manifest JSON (data/processed/, under 1 MB); returns (stack_path, manifest_path).
- `encode_hls(raw)` : DSWx-HLS WTR codes to 1 / 0 / 255.
- `encode_s1(raw, hand_masked_as='not_water')` : DSWx-S1 WTR codes to 2 (open water) / 1 (inundated vegetation, partial) / 0 / 255; HAND-masked pixels follow the rule `hand_masked_as`.
- `pixel_events(dates, series, min_obs_per_event=2, max_drain_window_days=12, dry_obs_to_separate_events=2, **_other_rules)` : flood events of one pixel: event count, first wet date, last wet date, first dry date, drain window, inundation days (min and max), and a status; nothing is interpolated across cloudy dates.
- `profile_stack(dates, stack, view, rules)` / `binary_water(states, view)` / `load_rules(path=RULES_CSV)` : the same logic for a whole stack; view is open_water (the flood signal) or any_water (context only); rules from data/reference/field_profile_rules.csv.
- `write_layers(district, grid, dates, stack, entries, out_dir, rules=None, jrc=None, jrc_info=None, built=None)` : saves GeoTIFF map layers and a layers manifest (files stay outside git).
- `field_profile(lat, lon, district=None, source='local', layers_dir=None, cache_dir=None)` : the flood history of the 30 m pixel at a point, with provenance; outside the 20 km box or without layers it returns covered False, never zeros. source 'hf' downloads the district layers first (hf.py).
- `merge_water(*arrays)` : same-date merge: water wins; no observation only if every input is missing.
- `district_grid(district, size_m=AREA_SIZE_M, res=RES_M)` : the fixed 30 m UTM grid and lon/lat bounding box of the district box (same grid as scripts/fetch_dswx.py --area).
- `validate_manifest(m)` : list of problems; every date needs a granule ID and a source URL.
Inputs (data files / other modules) and their provenance: NASA CMR + LP DAAC/PO.DAAC granules OPERA_L3_DSWX-HLS_V1 and OPERA_L3_DSWX-S1_V1 (read through earthaccess with EARTHDATA_TOKEN from .env); class codes in data/reference/opera_classes.csv (OPERA product specs D-107395 Rev B and D-108761 Rev A, Table 4-1). Reuses cached S1 windows in cache/dswx_area/ when present (same grid).
Outputs (shape + units + provenance fields): stack `water_stack_<start>_<end>.npz` in `<out_dir>/<district>/` with `dates` (UTC) and `water` uint8 [dates, 667, 667]; manifest `data/processed/field_profile_manifest_<district>.json` with grid, per-date granule IDs per product, source URLs and pixel shares (water / not water / no observation) per product and merged.
Reference tables used (data/reference/*.csv rows): opera_classes.csv (13 rows), field_profile_rules.csv (project rules, not from the OPERA spec).
Tests (file names + what each proves): tests/field_profile/test_events.py (event, drain-window, cloud-gap and paddy cases), tests/field_profile/test_layers_api.py (layers, field_profile answers, not-covered, JRC label, hf source), tests/field_profile/test_field_profile.py: class encoding equals the cited table, unknown codes raise, merge rule, grid snapping, manifest completeness, and a real 50 x 50 Feni river fixture (tests/fixtures/field_profile/) that reproduces the merge offline.
Known limitations / honest caveats: DSWx-S1 first date over Feni and Cumilla is 21 Aug 2024 (CMR, searched back to 1 Jan 2023); before that only HLS (cloud-limited in the monsoon). DSWx-S1 HAND-masked pixels (250) are encoded as "not water" (our decision, not in the spec); inundated vegetation (3) and HLS partial water (2) count as water. Same-day granules are merged by UTC sensing date. No inundation-day or drain-date metric yet (T3b). Raw rasters stay in data/raw/ (gitignored).
